## 为什么配额重置时间未变化？

### 技术原因

配额重置时间（`rateLimitResetTimes`）的更新机制：

1. **设置时机**: 仅在收到 `RESOURCE_EXHAUSTED` (429) 错误时设置
2. **更新来源**: 从 API 响应的 `Retry-After` 或错误详情中提取
3. **预热操作**: 只刷新 OAuth 令牌，**不触发** 429 错误

**代码证据** (`src/plugin/recovery.ts`):
```typescript
function extractRetryAfter(errorBody: any): number | undefined {
  // 从 API 错误响应中提取重置时间
  // 只有在真实请求被限流时才会调用
}
```

### 这是正确的行为

配额预热的目标是：
- ✅ **刷新令牌** - 确保账号认证有效
- ✅ **准备就绪** - 当配额重置时立即可用
- ❌ **不是**修改配额重置时间

**类比**:
- 汽车预热：启动发动机让引擎热起来（刷新令牌）
- 不是：改变外部温度（配额重置时间）

配额重置时间由 **Google 后端系统** 控制，客户端只能：
1. 记录上次被限流的时间
2. 在重置前预热准备
3. 重置后自动清除记录
